應用程式可以請你簽署一筆 Hive 交易，例如一次投票、一次轉帳或一篇文章。它們會送來一個開啟 Hivesigner 的連結。Hivesigner 用淺白的文字說明這個請求做什麼、需要哪把金鑰，以及之後會把你送到哪裡。在你核准之前，不會簽署任何內容。應用程式也可以請你簽署一則訊息，而訊息永遠不會上鏈。

## 「確認交易」畫面 {#confirm-screen}

簽署連結會開啟標題為「確認交易」的畫面。請求中的每一項操作對應一張卡片。操作是 Hive 上的一個動作，例如一次投票或一次轉帳。

當一個請求包含多項操作時，卡片會編號，上方一行寫著「這個請求包含 3 項操作。核准前請逐一檢查。」

### 摘要 {#summary}

每張卡片以一句話開頭，用請求中的數值說明該操作做什麼。例如：

| 操作 | 卡片上的內容 |
| --- | --- |
| 轉帳 | 傳送 1.000 HIVE 給 @bob（下方顯示備註，形如「備註：...」） |
| 投票 | 對 @alice/my-post 投贊成票（下方顯示投票權重，例如 100%） |
| 文章或回覆 | 發布文章「我的標題」，或 回覆 @alice/my-post |
| Hive 應用程式自訂的動作 | 自訂動作（follow） |
| 更改帳號控制權 | 更新帳號權限 |

其他操作會顯示各自的名稱，例如「轉為 Hive Power（Power Up）」或「委派 Hive Power」。

這句話旁邊有一個大寫標籤，說明該操作需要哪把金鑰：發文、活躍或擁有者。

### 詳細資料 {#details}

在這句話下方，卡片會列出該操作帶有的各項數值：

- 該操作以哪個帳號的身分執行
- 文章或留言：永久連結（文章的位址）、社群或標籤、內文與中繼資料
- 自訂動作：資料中的每個值各佔一行，確保內容不會被截斷
- 權限變更：它所設定的門檻、金鑰與帳號

權限變更如果會移除你的金鑰，也會用「金鑰：【無】（你的金鑰將被移除）」說明。缺少門檻時顯示為「門檻【未設定】（簽署時視為 0）」。

在摘要與詳細資料中，可能隱藏文字或改變文字方向的字元會顯示為 `�`。你讀到的內容不可能偽裝成別的東西。

**顯示原始操作**會展開即將簽署的確切操作。

當金額以 Hive Power 表示時，Hivesigner 會依目前比率換算。它會顯示「正在載入目前的 Hive Power 換算比率……」，並在取得該比率之前不允許核准。

有些請求帶著在別處準備好的交易，例如由多人共同控制的帳號。這時畫面會顯示「這個請求自帶交易標頭。到期時間：日期。」如果已有其他人簽署過，還會補上「它已附有 2 個簽章。」

## 需要哪把金鑰 {#which-key}

卡片下方有一行說明整個請求需要的金鑰：「將以你的發文金鑰簽署」「將以你的活躍金鑰簽署」或「將以你的擁有者金鑰簽署」。

Hivesigner 只用那把金鑰簽署。活躍金鑰不能簽署投票，擁有者金鑰也不能簽署轉帳。這是 Hive 自 2025 年一次硬分叉以來的規則。參見[該新增哪把金鑰](/docs/accounts#which-key)。

同一個請求中的所有操作必須需要同一把金鑰。若非如此，這一行會寫著「這筆交易需要多種權限，無法只用一把金鑰簽署。」畫面上沒有核准按鈕，請返回應用程式。

使用擁有者金鑰的請求很少見。它們會改變誰能控制或救援你的帳號，請讀兩遍。參見[核准前先讀](/docs/safety#read-before-approving)。

### 缺少金鑰時 {#missing-key}

如果已選取的帳號在這個裝置上沒有相應金鑰，畫面會說明。例如：「此操作需要活躍金鑰，但這個裝置上沒有 @使用者名稱 的活躍金鑰。」

1. 選擇提示下方的**新增其他帳號**，會開啟**新增帳號**表單。
2. 輸入同一個使用者名稱和缺少的那把金鑰。如果該帳號設有本機密碼，也一併輸入。
3. 選擇**新增帳號**。Hivesigner 會新增金鑰並把你帶回請求。

如果帳號處於鎖定狀態，畫面會在按鈕上方顯示**本機密碼**欄位。按一次就能解鎖並核准。若解鎖後發現確實缺少金鑰，畫面會隨即說明。

如果這個瀏覽器還沒有任何帳號，按鈕會顯示**繼續**並開啟**新增帳號**表單。

## 核准或簽署 {#approve}

按鈕上方的帳號列寫著「簽署帳號」以及執行簽署的帳號。**切換帳號**可以另選一個。參見[切換帳號](/docs/accounts#switch-accounts)。

- **核准**會在你的瀏覽器中簽署交易並送到 Hive 網路。結果顯示「交易已成功廣播」，並附上一個可在區塊瀏覽器中開啟該交易的**交易 ID**。
- 當請求只索取簽章時，出現的則是**簽署**。Hivesigner 會簽署交易但不送到網路，把簽章交給應用程式；如果請求沒有指定網站，就直接顯示出來。

如果網路拒絕了這筆交易，你會看到「你的交易未廣播」以及網路給出的「錯誤訊息」。你可以再試一次。

## 你將返回的網站 {#return-site}

當請求指定了返回的網站時，頂端提示會寫著「你將被重新導向至 HOST。」核准後 Hivesigner 會把你送到那裡。請確認 HOST 就是你來的那個網站。

當請求沒有指定網站時，Hivesigner 會停留在結果畫面。

## 給其他帳號的請求 {#another-account}

請求可能是針對已選取帳號以外的另一個帳號。Hivesigner 會用兩種方式提示。

**該請求必須由另一個帳號簽署。** 畫面顯示「這個請求必須由 @帳號 簽署。請切換到該帳號。」帳號列顯示「已選取的帳號」，其下展開帳號清單。請選取那個帳號，或用**新增其他帳號**把它加進來。Hivesigner 不會用任何其他帳號簽署這個請求。

**某項操作以另一個帳號的身分執行。** 這常見於多人共同管理的帳號。頂端的警告寫著「此操作不是以 @使用者名稱 的身分執行，而是以 @帳號 的身分執行。只有在你也管理該帳號時才繼續。」每張卡片的詳細資料都會寫明它以哪個帳號的身分執行。

## Hivesigner 無法讀取的請求 {#invalid-requests}

Hivesigner 絕不會簽署它無法完整讀取並呈現給你的請求。這包括它不認得的操作、沒有任何操作的請求、與操作不符的值（不是數字的數字、格式錯誤的金額），以及它無法顯示的多餘資料。

這時畫面會顯示「糟糕，發生錯誤。提供的資料無效。」請返回應用程式。若要告知 Hivesigner 團隊，請選擇**回報這個問題**。

## 訊息簽署請求 {#message-requests}

有些應用程式請你簽署一則訊息而不是一筆交易，例如用來證明某個帳號屬於你。訊息只是文字，簽署它不會改變區塊鏈上的任何內容。

畫面會顯示：

- 類似「應用程式 請你簽署一則訊息。」的標題。如果該應用程式有 Hive 帳號，下一行會寫明：「Hive 帳號 @應用程式帳號」。
- 「將前往 HOST」：接收簽章的網站。同一行會在按鈕旁再出現一次。
- **訊息**：將被簽署的完整文字，一字不差。可能隱藏文字或改變文字方向的字元會顯示為醒目的編碼，例如 `\u{200B}`。
- 使用的金鑰：「將以你的發文金鑰簽署」或「將以你的活躍金鑰簽署」。Hivesigner 絕不會用擁有者金鑰簽署訊息。
- 一則警告：「你的簽章會向任何看到它的人證明 @使用者名稱 簽署了這段確切的文字。只簽署你理解的訊息。」
- 帳號列「簽署帳號」，以及**切換帳號**。

選擇**簽署**即可簽署。Hivesigner 會把你送回該網站，並附上簽章、你的使用者名稱、金鑰類型，以及產生這個簽章的公開金鑰。公開金鑰是金鑰組中可以公開的一半，它本身簽不了任何東西。

選擇**取消**會前往**帳號**頁面，該網站什麼都收不到。

如果帳號在這個裝置上沒有相應金鑰，畫面會說明。例如：「此操作需要發文金鑰，但這個裝置上沒有 @使用者名稱 的發文金鑰。」請選擇**切換帳號**，再選擇**新增其他帳號**，為同一個帳號[補上缺少的金鑰](/docs/accounts#add-a-key)。Hivesigner 會把你帶回請求。

### 有些訊息為何被拒絕 {#refused-messages}

**可以當成 Hivesigner 登入憑證的訊息。** 有些文字的格式和 Hivesigner 的登入憑證完全相同。簽署它就等於把帳號存取權交給該網站。Hivesigner 絕不簽署這類文字，並會說明「這則訊息是 Hivesigner 權杖。簽署它會讓該網站取得你帳號的存取權，因此無法簽署。」

**Hivesigner 無法使用的請求。** Hivesigner 會拒絕沒有訊息或沒有返回位址的請求，也會拒絕索取發文金鑰與活躍金鑰以外金鑰的請求、把不是 Hive 帳號的東西當成應用程式的請求，以及返回位址不安全或未向該應用程式註冊的請求。它會說明「這個簽署要求無法使用：它需要一則訊息、一把發文或活躍金鑰，以及為該應用程式註冊的安全重新導向網址。請回到該網站再試一次。」

如果 Hivesigner 無法從 Hive 網路讀取應用程式的資料，會顯示「無法從 Hive 網路載入帳號資料。」在讀取成功之前，它什麼都不會簽。請選擇**重試**。

## 自己簽署一則訊息 {#sign-message}

你可以自行簽署一則訊息，用來證明自己掌控著某個帳號。

1. 開啟 [hivesigner.com/signmessage](https://hivesigner.com/signmessage)。頁尾以**簽署訊息**連到那裡。
2. 如果已選取的帳號處於鎖定狀態，請輸入本機密碼並選擇**解鎖**。如果沒有選取任何帳號，頁面會給出通往帳號清單的連結。
3. 在**訊息**中輸入文字。Hivesigner 會去掉開頭和結尾的空白與換行。
4. 在**用來簽署的金鑰**中選擇金鑰。那裡依由強到弱列出已選取帳號在這個裝置上的金鑰，一開始選中最強的那把。除非你需要別的金鑰，否則請改為**發文**。
5. 選擇**簽署訊息**。

**簽章摘要**會顯示**簽署者**、**使用的權限**、一個**驗證權杖**和一個**驗證連結**。驗證權杖把訊息、你的使用者名稱和簽章合在一段文字裡。請把連結或權杖交給需要核對這則訊息的人。

簽章不會洩漏你的金鑰，但會顯示它是由哪把金鑰產生的。

## 驗證一則訊息 {#verify-message}

1. 開啟 [hivesigner.com/verifymessage](https://hivesigner.com/verifymessage)。頁尾以**驗證訊息**連到那裡。
2. 把權杖貼到**驗證權杖**中，然後選擇**驗證簽章**。

驗證連結會開啟這個頁面並自動完成核對。

結果會顯示「簽章有效，簽署者為 使用者名稱」或「無法以帳號金鑰驗證這個簽章。」下方會列出**簽署者**、**還原出的公開金鑰**、**相符的權限**（完成簽署的金鑰類型）和**訊息**。

Hivesigner 會用該帳號目前在 Hive 網路上的金鑰來核對簽章。如果帳號此後換過金鑰，用舊金鑰簽署的訊息就不再能通過驗證。
